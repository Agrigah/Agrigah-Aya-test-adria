# Partie I — Réponses courtes DevOps

**Secrets vs configuration.** La configuration (ports, URLs, plafond `bank.transaction.max-amount`, nom des topics) n'est pas sensible : elle vit dans le dépôt / le config-service, versionnée et propre à chaque environnement. Les secrets (clé API du LLM, mots de passe, token de registre, clé SSH) ne sont jamais committés ni mis dans l'image : ils sont injectés à l'exécution par variables d'environnement (`.env` ignoré par git en local, *GitHub Actions secrets* en CI, Docker/Kubernetes secrets ou Vault en production) et peuvent être tournés sans reconstruire l'image.

**Contrôles de démarrage, disponibilité, vitalité.** Spring Boot Actuator expose `/actuator/health/liveness` (vitalité : le process n'est pas bloqué, sinon redémarrage) et `/actuator/health/readiness` (disponibilité : prêt à recevoir du trafic, dépendances OK). Un contrôle de démarrage (*startup probe*) laisse le temps au service de démarrer avant que liveness ne s'applique. Dans `docker-compose.yml`, un `healthcheck` + `depends_on: condition: service_healthy` ordonnent le démarrage (Eureka → Config → services → gateway).

**Logs, métriques, traces.** Logs structurés (JSON) écrits sur stdout, collectés par Loki/ELK ; métriques Micrometer exposées via `/actuator/metrics` (ou `/actuator/prometheus`) et scrappées par Prometheus, visualisées dans Grafana (état des circuit breakers, latence, lag Kafka) ; traces distribuées avec Micrometer Tracing + OpenTelemetry vers Zipkin/Jaeger, grâce à un `traceId` propagé à travers Gateway → Feign → Kafka pour suivre une requête de bout en bout.

**Stratégie de rollback.** Les images sont immuables et taguées avec le SHA du commit : revenir en arrière = redéployer le tag précédent (`TAG=<sha-précédent> docker compose up -d`). Un déploiement progressif (rolling / blue-green / canary) avec les probes de disponibilité permet de stopper et revenir automatiquement si la nouvelle version échoue. Les migrations de base de données doivent être rétro-compatibles (Flyway, étapes « expand / contract ») pour qu'un rollback applicatif ne casse pas le schéma.
